\subsection{RQ5: reference points}
\label{sec:rq_reference}

Table~\ref{tab:baselines} places our views next to re-implementations of the
\emph{input representations} used by existing approaches, a pretrained code
model, and the trivial size rule, all on the same samples and folds.
They are not reproductions of the published systems or their published numbers,
which use different data splits and often within-project evaluation.

\input{tab_baselines}

\paragraph{Devign/ReVeal-style input.} Text together with the node type
(\texttt{lex+$\kappa$} with a GGNN) reaches AUC \mBvGgnnLexKindAuc{} on BigVul
and \mDvGgnnLexKindAuc{} on DiverseVul, which is below the grammar-kind and anonymised views in
Table~\ref{tab:rq2_representation}.

\paragraph{A pretrained code model.} UniXcoder~\cite{guo2022unixcoder} with a frozen
encoder and a linear probe on the raw source (identifiers included) reaches AUC
\numbvUnixAuc{} on BigVul and \numdvUnixAuc{} on DiverseVul. On BigVul the
probe is higher than the GNN with grammar kinds, but not significantly (the
paired difference of $\kappa$ against it is \cBvGgnnKindVUnixD{},
\cBvGgnnKindVUnixLo{} to \cBvGgnnKindVUnixHi{}); on DiverseVul it is below (\cDvGgnnKindVUnixD{}, \cDvGgnnKindVUnixLo{} to
\cDvGgnnKindVUnixHi{}). Two lessons follow. First, ``text hurts cross-project
transfer'' is a statement about token embeddings learned from scratch on a few
thousand functions, not about text in general: a model that has seen billions
of code tokens before can use identifiers and still transfer. Second, a
vocabulary-free GNN trained from scratch is competitive with, not clearly
better than, a frozen pretrained model. The probe is frozen and untuned; a
fine-tuned LineVul-style model~\cite{fu2022linevul} would probably be stronger,
and we have not run one because this machine has no GPU.

\paragraph{The size rule beats everything.} Scoring a function by its node count
alone gives AUC \numbvSizeAuc{} (BigVul) and \numdvSizeAuc{} (DiverseVul),
above every network in this study including the pretrained probe on BigVul.
The paired differences are in the last rows of the analysis files
(e.g.\ $\kappa$ against size: \cBvGgnnKindVSizeD{}, \cBvGgnnKindVSizeLo{} to
\cBvGgnnKindVSizeHi{} on BigVul). We read this as a caution about the whole
benchmark family: under project-disjoint evaluation, much of what these
corpora reward is a length prior, and absolute AUCs of $0.6$ to $0.7$ should not
be read as evidence of vulnerability understanding.
