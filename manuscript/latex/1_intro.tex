\section{Introduction}

Software vulnerabilities are a critical and growing threat to modern computing systems. The National Vulnerability Database (NVD) reported over 25,000 new Common Vulnerabilities and Exposures (CVEs) in 2024 alone, highlighting the urgent need for automated and scalable vulnerability detection mechanisms. While Deep Learning-based Vulnerability Detection (DLVD) methods have demonstrated significant promise, they continue to suffer from two fundamental barriers that impede their adoption in real-world scenarios: the generalisation gap and the data silo problem.

First, state-of-the-art DLVD models exhibit a catastrophic \emph{generalisation gap} when applied across different software projects \cite{chakraborty2022deep}. For instance, a model trained on the source code of FFmpeg typically fails to reliably detect vulnerabilities in OpenSSL, even when both projects manifest the identical Common Weakness Enumeration (CWE) type. Replication studies consistently report performance drops of 50\% to 90\% in cross-project evaluation settings compared to within-project evaluations \cite{chakraborty2024realvul, ding2025primevul}. This degradation occurs because existing models tend to overfit to project-specific lexical patterns (e.g., API names, variable naming conventions) rather than learning the underlying structural semantics of the vulnerability.

Second, the \emph{data silo problem} prevents the aggregation of sufficient training data. Real-world vulnerability data is highly sensitive and routinely proprietary. Organisations such as financial institutions, cloud service providers, and defence contractors cannot legally or practically share their raw source code with external entities due to intellectual property concerns and privacy regulations. Consequently, a centralised DLVD model trained on one organisation's codebase cannot leverage the knowledge embedded in another organisation's repositories, severely restricting the model's exposure to diverse vulnerability manifestations.

Federated Learning (FL) has emerged as a promising paradigm to address the data silo problem by enabling collaborative model training without centralising raw data \cite{mcmahan2017fedavg, abadi2016deep}. However, naively applying standard FL techniques, such as FedAvg, to vulnerability detection does not resolve the generalisation gap \cite{he2021fedgraphnn}. Weight averaging across highly heterogeneous, non-IID (Independent and Identically Distributed) codebases fails to transfer structural vulnerability knowledge effectively, leading to suboptimal cross-project detection performance \cite{yamamoto2023flr, hu2024vulfl}.

The root cause of both barriers stems from the representation level: existing approaches primarily model code at the lexical or token level rather than at the structural or semantic level \cite{li2018vuldeepecker, zhou2019devign}. A buffer overflow in FFmpeg and a buffer overflow in OpenSSL are structurally identical within their Code Property Graphs (CPGs)---both typically involve a loop incrementing an index, an array access using that index, and a missing bounds check---yet they utilise completely different function names and API calls. 

To overcome these challenges, we propose \textbf{VulMorph-Fed} (Vulnerability Morphology-Guided Federated Learning), a novel federated learning framework designed to achieve robust cross-project vulnerability detection while preserving data privacy. VulMorph-Fed operates on the principle that vulnerability patterns are structurally invariant across projects but lexically heterogeneous. By extracting and federating \emph{vulnerability morphologies} rather than raw parameters or lexical features, VulMorph-Fed successfully bridges the generalisation gap without requiring centralised code sharing.

The primary contributions of this paper are:
\begin{itemize}
    \item We introduce the \textbf{Vulnerability-Critical Subgraph Abstraction (VCSA)}, which combines a fully specified, deterministic mapping of code tokens onto a small taxonomy of abstract semantic operation types (given exhaustively in Table~\ref{tab:taxonomy}) with a learned, trainable edge-weighting module that down-weights vulnerability-irrelevant structure.
    \item We propose \textbf{Morphology-Conditioned Federated Prototype Aggregation (MCFPA)}, an FL aggregation mechanism that shares CWE-conditioned semantic prototypes instead of model parameters. We prove a per-round $\varepsilon$-differential-privacy guarantee for the released prototype bank (Proposition~\ref{prop:dp}) with explicit norm clipping, per-class noise calibration, and sequential-composition accounting over rounds.
    \item We design \textbf{Morphology-Guided Message Passing (MGMP)} to inject global prototype signals into local Graph Neural Network (GNN) training, allowing clients to benefit from structural knowledge of CWE types they have never observed locally.
    \item We evaluate on project-level cross-project splits of four public corpora with multi-seed repetition, statistical testing, and a baseline suite designed to isolate the representation from the federation mechanism (including FedAvg on our own abstracted representation and a centralised variant of our full model). We release the complete implementation and the scripts that regenerate every reported number.\footnote{\url{https://github.com/vinhqdang/vulmorph-fed}}
\end{itemize}
